# Astro Sushil: Phase 0 Security & Data Integrity Audit

**Document Reference:** `docs/audits/report_system/PHASE_0_SECURITY_AND_DATA_INTEGRITY.md`  
**Classification:** Security, Authorization & Data Integrity Audit  
**Date of Audit:** November 3, 2026  
**Status:** Completed; Vulnerabilities and Risks Documented  

---

## 1. Executive Summary

This audit evaluated data security, tenant isolation, access authorization, persistence immutability, and asset distribution across the Astro Sushil report generation architecture.

The audit verified that user authorization guards and signed URL mechanisms in `apps/api` are largely sound, but identified **high-risk concerns** regarding local `/tmp` filesystem storage fallbacks, lack of cryptographic checksum validation on stored PDF artifacts, and concurrency race conditions in report caching queries.

---

## 2. Authorization & Tenant Isolation Audit

### 1. User & Birth Profile Access Controls
- **Endpoint:** `POST /api/v1/reports/request`
- **Authentication:** Enforces JWT Bearer authentication (`fastify.authenticate`).
- **Profile Ownership Verification:**
  In `apps/api/src/modules/reports/reports.service.ts` (`requestReport`):
  ```typescript
  if (dto.birthProfileId) {
    const profile = await prisma.birthProfile.findUnique({
      where: { id: dto.birthProfileId },
    });
    if (!profile || profile.userId !== userId) {
      throw new ForbiddenException('You do not have permission to access this birth profile');
    }
  }
  ```
- **Finding:** **SECURE.** A customer cannot request a report for a birth profile belonging to another user. If `profile.userId !== userId`, the API terminates the request with HTTP 403 Forbidden.

### 2. Generated Report Download Authorization
- **Endpoint:** `GET /api/v1/reports/:id/download`
- **Ownership Verification:**
  In `apps/api/src/modules/reports/reports.service.ts` (`getReportDownloadUrl`):
  ```typescript
  const report = await prisma.report.findUnique({ where: { id: reportId } });
  if (!report) throw new NotFoundException('Report not found');
  if (report.userId !== userId && userRole !== 'ADMIN' && userRole !== 'SUPER_ADMIN') {
    throw new ForbiddenException('You do not have access to download this report');
  }
  ```
- **Finding:** **SECURE.** Direct Object Reference (IDOR) attacks are prevented. Standard customers cannot download reports generated by other users.

### 3. Signed URL Expiration & Asset Delivery
- **Mechanism:** Handled via `StorageService` (`apps/api/src/services/storage.service.ts`).
- **Cloudflare R2 Integration:** When configured, generates time-limited S3 pre-signed `GetObject` URLs with an expiration of **900 seconds (15 minutes)**.
- **Finding:** **SECURE.** Direct bucket URLs are never exposed. Asset access tokens expire automatically.

## 3. Storage Security & Persistence Risks

### Risk 1: Insecure Local Filesystem Storage Fallback (HIGH RISK)
- **File:** `apps/api/src/services/storage.service.ts` (lines 35–52)
- **Behavior:**
  When cloud storage credentials (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`) are missing or unconfigured in development or staging environments, the service falls back to storing generated PDF files on the local filesystem:
  ```typescript
  const localBasePath = process.env.LOCAL_STORAGE_PATH || '/tmp/astro-sushil/storage/reports';
  ```
- **Vulnerabilities:**
  1. `/tmp` is a shared OS directory typically mounted as `tmpfs` (RAM-backed) on Linux systems. Many Linux operating systems clean `/tmp` periodically (via `systemd-tmpfiles-clean`) or upon server reboots.
  2. If the server restarts or the temporary directory is cleaned, existing customer reports stored locally vanish permanently, while the database records continue pointing to non-existent file paths.
  3. Storing sensitive customer astrological dossiers containing full names, birth dates, and geographical coordinates in an unencrypted `/tmp` partition violates data security best practices.

### Risk 2: Concurrency Race Condition in Report Caching (MEDIUM RISK)
- **File:** `apps/api/src/modules/reports/reports.service.ts` (lines 85–115)
- **Behavior:**
  To prevent duplicate generation, the API queries for an existing report with the same parameters:
  ```typescript
  const existingReport = await prisma.report.findFirst({
    where: {
      userId,
      birthProfileId,
      reportType,
      status: { in: ['COMPLETED', 'PROCESSING'] },
    },
  });
  if (existingReport) {
    return existingReport;
  }
  ```
- **The Race Condition:**
  If a customer double-taps the "Generate Report" button on their mobile device, two near-simultaneous HTTP requests arrive at the Fastify server.
  Because there is no atomic database constraint or distributed Redis lock prior to the `findFirst` query, both requests observe `existingReport === null`, and both enqueue independent BullMQ background jobs.
  This leads to duplicate BullMQ worker executions, duplicate XeLaTeX compilations, and duplicate PDF files generated for the same transaction.

### Risk 3: Absence of Cryptographic Integrity Checksums (LOW RISK)
- **Finding:**
  When reports are persisted to storage and recorded in the `reports` table, only `fileSize` (bytes) and `pagesCount` (integer) are stored.
  No SHA-256 or MD5 cryptographic hash is computed or stored. Consequently, if a report file on storage is corrupted, replaced, or truncated during upload, the platform cannot detect the integrity failure.

## 4. Background Worker Security & Job Lifecycle

1. **Job Isolation:**
   - BullMQ executes jobs inside independent job contexts in `report-worker.service.ts`.
   - Temporary compilation directories (`/tmp/astro-report-*`) are created with unique UUID suffixes for each job and unlinked via `rm -rf` upon completion.
   - Cross-job file leakage does not occur.
2. **Failure Telemetry:**
   - When XeLaTeX compilation or AI generation fails, the worker updates the database record status to `FAILED`, storing the error message in the `metadata` JSON field.
   - Error messages are sanitized and do not leak database credentials, internal server tokens, or secret keys.
